# rikitikitavi

Home-network security auditor in Rust. Workspace of nine crates under `crates/`.
User docs: `README.md`. Threat model: `SECURITY.md`. Open work: `docs/ROADMAP.md`.

## Crates

| Crate | Holds |
|---|---|
| `rikitikitavi` | Binary: CLI (`cli.rs`), command dispatch (`main.rs`), scan runner, accept ledger (`accept.rs`) |
| `rikitikitavi-core` | `Severity`, `Perspective`, `ScanError` |
| `rikitikitavi-models` | `Finding`, `Device`, `ScanContext`, config types |
| `rikitikitavi-network` | Interfaces, routes, ARP, WiFi (Linux `/proc`, macOS commands) |
| `rikitikitavi-scanners` | `Scanner` trait (`traits.rs`), one file per scanner, generated `*_db` tables |
| `rikitikitavi-analysis` | Risk scoring, device grades, attack paths, KEV/EPSS tables, scan diff, scan history |
| `rikitikitavi-export` | JSON, CSV, HTML, OCSF, Prometheus, fix plan, segment plan |
| `rikitikitavi-tui` | ratatui interface |
| `rikitikitavi-unifi` | UniFi controller client and audit |

## Before every commit

All of these must pass; CI runs the same set.

```sh
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy -p rikitikitavi --features otel --all-targets -- -D warnings
cargo test --workspace
cargo +1.89 check --workspace      # MSRV
cargo deny check
```

After pushing, check the CI run for that commit's SHA, not the latest run.

## Rules for the code

- `unsafe_code = "forbid"`. Clippy `pedantic` and `nursery` are on with `-D warnings`.
  Fix the lint; add `#[allow]` only when the fix makes the code worse.
- Comments: few, terse, facts about the code only. No history, no rationale essays.
- Library crates use `thiserror`; the binary uses `anyhow`.
- Everything read from a LAN device is untrusted. Read HTTP bodies with
  `http_util::read_body_capped`; bound every buffer, loop and timeout.
- Parsers take `&str` or `&[u8]` so they can be tested and fuzzed without I/O.
  New parsers of device input get a fuzz target (`fuzz/README.md`).
- `*_db.rs` tables are generated by `scripts/gen_*.py`. Edit the script, not the table.
- Finding titles feed `Finding::fingerprint()`, which the accept file and scan
  diff key on. Changing a title changes the fingerprint; say so in `CHANGELOG.md`.
- Remediation text lives in `rikitikitavi-scanners/src/remediation.rs`, keyed by rule id.
- User-visible changes get a `CHANGELOG.md` entry under `Unreleased`.

## Rules for running it

- Scan only the owner's own network. Never pass `--aggressive` unless the user asks
  for it in that message.
- Do not log in to, or send requests to, a UniFi controller unless the user asks.
- `scan`, `tui`, `verify` and `watch` send traffic to the LAN. `--help`, the tests
  and the exporters do not.
- Saved scans are in `~/.local/share/rikitikitavi/scans/`. They contain the user's
  device inventory; do not paste them into anything that leaves the machine.

## Checking output you cannot see

- TUI screens: render with ratatui's `TestBackend` and read the text
  (`crates/rikitikitavi-tui/tests/screens.rs` shows how).
- ASCII art (`crates/rikitikitavi-tui/src/art.rs`, `README.md`): render to a PNG in
  a monospace font and look at the image before committing a change.
- Markdown exports have golden files next to their module
  (`crates/rikitikitavi-export/src/{fix_plan,segment_plan}/golden.md`).
